# 经验条目模板

文件放在 `docs/lessons/<英文短横线名>.md`，每条经验一个文件。

```text
# <情境短句>

情境：<问题的形态，换一件事也能用上；不写这次的具体事实>
做法：<针对本仓库代码、测试、命令、接口或数据的操作，能照着做、能检查；可以点明在设计、拆任务或写验收命令时用>
作用对象：`<本仓库路径>`，`<路径>`
证据：
- 有效：<改动> → <差异>，失败行 `<原文摘录>`（<任务标题>，<日期>）
- 用户纠正：<原话摘要>（<日期>）
置信度：高 | 中 | 低，<理由>
来源：<手册主题>，<日期>
引用记录：
- 无
```

## 规则

- 粒度：太泛的不收，如「要仔细」；太窄、再也用不上的不收，如「某日某接口返回 409」
- 流程类不收：做法换到无关仓库也照样成立，就属于流程类。「门禁先比对测试原文」是流程类；「这个仓库的真库测试在验收命令里要分段跑」是项目经验
- 作用对象至少写一个本仓库里存在的路径，路径放反引号里
- 证据每行以判定词开头：有效、有害、无可见效果、无法归因、用户纠正；至少一行是有效、有害或用户纠正，只靠无法归因或无可见效果撑着的不成经验
- 有效的标准：同一条验收命令修复前失败（摘录失败行）、修复后通过；修复只针对一处原因；没有靠重试通过。改坏了判有害；用户在运行中明确纠正的做法判用户纠正；拿不准一律判无法归因
- 证据的失败输出原文摘录放反引号里；不引用账本行、日志路径或提交号，手册和日志会被清理
- 引用记录：每行写 `- YYYY-MM-DD <手册主题>：<判定>，<一句观察>`，没有时写 `- 无`；设计稿引用过的经验在之后的复盘里各打一行判定并追加到这里，判有害就删除条目
- 不写任务编号、决策编号、验收编号、章节号和轮次号，用任务标题代替；不链接 `docs/miniplan/`
- 可固化的经验由用户另起任务做成测试、lint、钩子或规则后，删除该条
- 条目总数上限 30；满额时新条目入库前先淘汰一条：作用对象路径全部失效的优先，其次是最近一次被引用最早的，没被引用过的按来源日期
