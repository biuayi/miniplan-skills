# 待办

## 手册复盘与经验

一份手册跑完后做一次复盘，把有证据的经验留给以后的设计和手册。

要做的：

- 收尾时，对修过或失败的任务判断根因假设是否被重新过门禁证实：证实、未证实、无法归因。多处同时改动又没有单独验证、或只有一次执行支撑时，记为无法归因
- 每份手册最多留一条经验，写成「情境、做法、证据」三项：情境写问题的形态，不写这次的具体事实；做法要能照着执行和检查；证据指向账本行或门禁日志。没有就写「无」
- 能变成 lint 规则、钩子或测试的经验，优先变成这些，不写成提示词里的文字

待定事项：

- 经验存在哪：手册末尾、仓库里的独立文件，还是 AGENTS.md
- 下次设计或写手册时读不读、怎么挑相关的条目
- 旧条目怎么淘汰或合并，避免越积越多、过时的经验误导后面的任务

参考：Harness²（arXiv:2610.14224，代码 google-research/harness2）的反思会话与经验库。它的纪律可以借：逐条标「无法归因」、最多一条经验、证据不够就写 NO_ENTRY。它的缺陷要避开：入库只检查字段非空，不核对证据；库没有容量上限，也不淘汰旧条目。
